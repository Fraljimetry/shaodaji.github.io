# MathReader v403 — Recoverability and durable page-level equation OCR

**Date:** 2026-11-07 (Beijing UTC+08). **Required baseline:** v402 over the user-supplied authoritative v401 source. **Scope:** equation-margin *observations* and full-text reading-data recovery, not mathematical formula OCR or classifier changes.

## Production defect established by two actual Ahlfors exports

Both files have **the same 172-page SHA-256 PDF identity** `sha256:970cda290270daa397d0bd5a06da4e423bb548d1556e71c1135f54fd637ac949`. The first export (2026-11-07T02:29:44.432Z) contains 172 page-side **right-margin** records on 172 pages, **4,054 OCR lines** in all (168 records have nonempty lines), and full observation coordinates. The second export (2026-11-07T02:32:54.899Z), taken **after closing/reopening the PDF and reloading the webpage**, contains **0 margin OCR records** and **0 OCR lines**. Native PDF text and the published Equation/Structure/Results/Bibliography indexes survived; **underlying margin observations did not**. 

This is a **real production persistence failure**, not a merely unverified feature. The exports do **not** reveal whether the previous IndexedDB write failed, a write completed too late, evidence was rejected during load, or browser storage was unavailable/evicted. A deterministic root cause cannot be asserted from two JSON files. The v402 bulk payload would have been ~1.93 MB, **below** the 6-million-character v401/v402 snapshot cap: exceeding that cap does not explain this case.

Run `python mathreader/regression_tools/compare_margin_exports_v403.py FIRST.json SECOND.json` on any two full-text exports. The supplied failing pair yields `FAIL` with **172 missing records** by exact page/side. A third export after v403 restoration can be compared to the first, with exact source text/coordinate equality. This comparison does not start OCR and does not accept matching names alone when SHA identities disagree.

## v403 correction

1. **Commit each completed OCR page immediately** in its own version-2 `meta` IndexedDB key `equation-margin-page-v2:${SHA256_ID}|${side}|${page}` rather than waiting for all selected OCR pages and one large snapshot. This applies to the automatic margin-scanner and user-triggered meticulous OCR. Records have exact document SHA, original page count, page, side, unmodified OCR lines/geometry, and version.
2. **Read each record back after the transaction commits** and verify that the record matches the original. If IndexedDB rejects, times out, or silently discards a write, the record is **not acknowledged**. A single user-visible warning directs the user to export a backup. OCR does not silently claim persistence. Subsequent pages don't each wait through repeated blocked-storage timeouts; final export retries once. A blocked page-store or restore is limited to 5 seconds per storage operation. The warning is not a false claim that the OCR recognition failed.
3. **Load page records on PDF open** (and again when exporting) and reject wrong-document, wrong-page-count, malformed or duplicated keys. A corrupted page is skipped independently instead of deleting healthy records. An existing in-progress OCR Promise in memory is not overwritten by older stored data.
4. **Preserve v401/v402 caches** by reading legacy `equation-margin-v1:${SHA256_ID}` bulk snapshots and filling gaps not present in the new page journal. The legacy record is never rewritten; its valid observations are migrated to independently verified page records on export. Existing OCR indexes, edits, bookmarks, notes, reading location and non-OCR cache formats are unchanged except for the preexisting standard reading-data import behavior described below.
5. **Recover from a v401/v402 full-text export** through the existing **Import** button: the optional `fullDocumentText.pages[].equationMarginOcr` observation data is now accepted for the exact SHA-identical PDF, page-by-page validated and persisted, and reloaded into memory. It never creates equation labels, starts OCR, or overwrites a valid existing per-page journal record. Import can also be performed from the library/history screen before selecting the original PDF. An invalid document ID or malformed line payload fails closed. **Regular Import still restores the exported reading session**; if the user has changed annotations/notes since the first export, export their current reading data first to back them up.
6. **Expose durability in full-text exports:** `fullDocumentText.equationMarginOcrCoverage.persistence` is now `verified`, `failed`, or `no-evidence`. `verified` means currently present observations were acknowledged by local per-page writes or read from the local per-page journal; it does **not** prove survival of a future browser reload. Export still never triggers OCR.
7. **Forget** removes both the page-journal and legacy bulk evidence from the local database. Removal is distinct from merely closing the PDF. The storage cleanup is not claimed as proven against in-flight transactions still blocked in the browser; a real adversarial multi-tab test remains open.

## Exact replay and verification

- v403 `tests/equation_margin_page_journal_v403_regression.js`: **40 assertions passed**, including independent writes, geometry equality, simulated reopen, interrupted scan, partial rescan, thrown/quietly dropped writes, timeout, one warning, malformed records, foreign document, exact-SHA import, and no replacement of newer records. It exercises production **functions**, but storage is a deterministic in-memory stand-in.
- Existing v401 cache compatibility test: **17 assertions passed**, including old bulk snapshot import and new page-journal precedence.
- Chromium source-function export test: **7 assertions passed**, explicitly **mocked IndexedDB** and PDF.js; not a production PDF/OCR test.
- First actual Ahlfors JSON: **172 page-side records, 4,054 OCR lines** correctly parsed and replayed into independently stored page records; original text and coordinates matched all 172 records after read-back in Node. Approximate serialized page records: **1,947,658 bytes**. One local benchmark elapsed approximately **0.1–0.2 seconds** in mocked storage; **not** a browser disk or real production performance measurement.
- Final sequential suite: **47/47 Node** and **20/20 Python/Chromium** tests passed (see `regression/v403_release_gate.json`). No extra real-browser IndexedDB claim was made.
- JavaScript syntax and deterministic overlay replay verified during v403 packaging. See `regression/v403_patch_verification.json`.

## Instructions for real recovery / mandatory next production gate

1. Deploy the v403 root patch over v402. Ensure the page has loaded new versioned JS files.
2. **Keep both uploaded Ahlfors JSON files and your original PDF.** To recover lost observations, use the **first** JSON (timestamp **02:29:44.432Z**) with 172 records, **not** the second with zero.
3. With the original matching Ahlfors PDF open, use **Import** and choose the first JSON. Existing standard import behavior also restores the saved reading session; back up newer annotations and notes first if necessary. No OCR run should begin just from import.
4. Export with **Include detection data** and **Include full-document text** checked. Verify coverage: 172 page-side right-margin records, 4,054 lines, identical line text/geometry, `persistence: verified`. No need to rerun equation OCR.
5. Close the PDF, reload the webpage, reopen the **same** Ahlfors PDF, **do not OCR**, and export again. Compare the new JSON against the first using `compare_margin_exports_v403.py`. Both must have exact page/side observation text/coordinates and matching 172-page SHA identity; check the page count and no evidence from a different document.
6. Exercise a partial manual rescan, Stop OCR, switching documents, corrupt individual cache records, Forget, multiple browser tabs, and limited browser storage; measure real IndexedDB memory/quota/timing. Do not call these cases passed before exercising them in a browser with persistent storage enabled.

## Still unverified / important boundaries

The original web-browser failure is **reproduced** and mitigation implemented. **v403 production browser export→reload→export recovery is not yet independently observed here.** This environment cannot navigate Chromium to a persistent local HTTP/HTTPS browser origin because of administrative policy. Browser quota, eviction, private mode restrictions, delete-versus-in-flight-write ordering, multi-tab upgrades and physical-disk write timing remain outside this offline regression. A browser reporting `no-evidence` on reopen cannot on its own prove whether OCR was never run or browser data were evicted: retain export backups. OCR line persistence is not a guarantee of equation-label accuracy, mathematical transcription accuracy, or navigation correctness. Giusti `(A.1)` printed on p231 still requires real production OCR publication/navigation verification; v402’s bounded query is preserved unchanged.
