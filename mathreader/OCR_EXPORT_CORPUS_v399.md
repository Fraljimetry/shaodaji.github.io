# v399 — Seven full text exports, Ahlfors TOC precision, proof links, OCR progress, and UI wrapping

**Authoritative baseline:** v398 MathReader root-level patch applied over the complete v397 tree. **Release:** v399 patch only. New controls and scope remain unchanged: detection index included by default; full-document PDF text opt-in. No new OCR engine, forced page rescan, OCR model, automated formula transcription, file import behavior, or toolbar item.

## What the 7 real full-text exports actually establish

The user supplied seven v398 `mathreader.reading-data@1` exports: Ahlfors (172 PDF pages), Giusti (253), Simon (13), Yau (73), Yamabe (56), `SPS_1988__22__485_0` (18), and `geometrical_hypothesis_Banach` (10). Total **595 page records**. Exact file SHA-256, native text-bearing page counts and detection counts are in `regression/v399_seven_full_exports.json`; raw 1–17 MB user JSONs are **not** repackaged. All seven report `fullDocumentText.complete: true` and `fullDocumentOcr: not-stored`. `complete` means available native PDF.js page evidence was serialized for all pages; it does **not** establish an OCR transcription of all pages, or 100% recognition accuracy. Ahlfors has text items on 167/172 pages; the remaining five are not assumed to be blank or legible without examining printed images.

### Distinct defect classes and source-grounded fixes

1. **Ahlfors Bibliography incorrectly navigated to TOC page 6 instead of actual page 163.** The original PDF.js text contains a damaged old-book header `CONTEN1'S vii`, hyphen-numbered TOC entries such as `8-4. Regularity and global correspondence 116`, and `Bibliography 152`. The previous Contents recognizer required an exact `Contents` header and dot-only numbering, accepting the TOC item as a real heading. v399 accepts the verified header variant *only within a repeated TOC-row context*, supports hyphenated entries, and distinguishes terminal title rows with printed folios. Full 172-page PDF.js text-item replay: old **61** Structure entries including incorrect Bibliography p.6; new **60**, with correct Bibliography p.163.
2. **Ahlfors repeated `FOREWORD` on page 9 is a running head, not a second Foreword section.** Original page images and text-item geometry show the real title on page 8 and a substantially smaller top running head on the next page. v399 suppresses only measured, much smaller adjacent-page repeats of conventional unnumbered headings. The 59 other Structure titles and their page/ratio coordinates are unchanged. Original 4-page PDF.js fixture and full 172-page replay both cover these two defects.
3. **False mathematical proof references extracted from ordinary prose.** The broad case-insensitive Results reference expression read `example u` (Yamabe p.11), `remark X` (Yamabe p.18), `hypothesis X` (Yamabe p.19), `assumption f` (Ahlfors p.30), `theorem e` (Simon p.6) and `theorem a` (Giusti p.184) as named Results references. A single-letter reference now needs an *actually detected matching named Result*. Genuine `Theorem A`, appendix `Theorem C.lO` -> `Theorem C.10`, spaced numeric `theorem 2 .1`, and unresolved numbered references are preserved. Resolved references are canonicalized and duplicates/self-edges removed. The full 7-export replay covers **380 saved Results**, drops nine unconfirmed/self/duplicate references (including all six proven spurious cases), preserves every distinct resolved non-self reference, and does not alter Results' label/page/ratio. This is a *reference-precision* correction, not an OCR-engine accuracy gain.
4. **`OCR 28/49` misconstrued as document coverage for Ahlfors's 172-page PDF.** This is a planned **equation-margin image OCR** queue. `49` is the number of pages selected by the automatic gap/image plan; `28` is how many of those selected page-margin inspections had completed when the screenshot was captured. Native text extraction uses all `172` pages. v399 prefixes the short status with `Eq OCR` and explicitly states in the tooltip that only 49 selected pages are involved out of 172 and this **is not full-document OCR**. Recoveries (`+3`) are measured candidate labels, not all missing formulae.
5. **Orphan word in Settings and other narrow descriptive text.** v398's `Reading data always included. No OCR starts on export.` put `export.` alone on the last line in the user's desktop screenshot. v399 uses two explicit, concise lines: `Reading data is always included.` / `Export never starts OCR.`. A narrowly scoped `text-wrap: balance` rule also protects brief right-sidebar notes/help/descriptions at 204–330 px without changing typography or sidebar default width. Existing English/Chinese data attributes, checkboxes and export behavior are preserved.

## Scope / limitations / open defects

None of these seven exports contains stored full-document Tesseract/Texify OCR output. The 595-page replay proves **native text → detector** behavior, not image-to-text/formula semantics. No new 50-textbook fully verified OCR accuracy certification is claimed; page-wise glyph transcription, printed equation completeness (including Giusti's missing equation `(A.1)` on page 231), Ahlfors's five native-empty pages, and production browser worker behavior are not certified in this patch. Appending more browser tests cannot establish them without actual models and independently checked printed-page truth. Unresolved *numbered* proof references remain in the diagnostic data deliberately, because some refer to genuinely missed Results. Importing a portable detection snapshot continues to preserve its contents until user-triggered rebuild; ordinary locally inferred Structure uses cache version **50** and rebuilds from the original PDF under the prior version policy. Equation detection version remains **26**.

### Browser-runner timing qualification

During repeated browser runs, two older Chromium smoke tests (`p1_browser_smoke.py`, `meticulous_ocr_menu_browser_v390.py`) had intermittent failures when the entire suite ran in shared runner invocations; **both passed on direct standalone reruns**, as did the remaining 15 individual Python/Chromium scripts. The aggregate automated ledger deliberately retains its failure observations rather than changing their recorded outcomes. This does not establish browser flake-free reliability. A full all-green single execution has not been certified. The actual new Settings wrapping browser test and the v399 original-PDF text replays passed.

The full JS suite has passed 44/44. Production browser OCR engine accuracy remains unverified, independently of browser smoke results.
