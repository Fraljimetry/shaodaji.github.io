MathIllustrator · Complete working tutorial

Release 0.26.0 · Cut 25 (November 12, 2026). MathIllustrator is a standalone browser-first mathematical figure editor. Its native project is a semantic JSON scene, not a raster screenshot. It is independent of MathReader and does not upload drawings or run remote math inference.

Scope matters: this is an expanding 2D editor, not yet a complete mathematical visualization platform. A feature listed as planned or disabled below is not available. Even implemented features have documented boundaries and verification levels. SVG/PNG/JPEG/WebP and a restricted TikZ/tikz-cd interchange are working; full PDF, 3D, Möbius transforms and Ricci-flow visualization are not yet implemented.

Where to find it: the website homepage has a Mathematical software section and the Tools page has a MathIllustrator launch link. The editor itself lives at /mathillustrator/. After copying the root-relative ZIP, you must deploy the repository for the public homepage to change.

1 · The three-panel workspace

The left panel contains a command line, searchable object list (newest objects above older ones), visibility and lock toggles, selection and object properties. The center is a zoomable Cartesian SVG design surface: positive x points right, positive y points up. The right panel contains icon-caption tool tiles, workspace presets, toolkit visibility switches and construction settings. Either side panel can collapse independently. On narrow screens, both panels initially collapse into side rails; click the left/right rail arrows to open and close the scrollable objects/tools drawers. The drawer offset follows the actual header height.

The object list uses a windowed rendering strategy for large projects (45-pixel rows, with overscan) while retaining the complete project and scroll/search access. The visible list preserves drawing order; bringing an object forward or backward changes its visual layer. Enter a query in Find objects to filter rows without deleting anything. You can keep hidden objects in the list, or uncheck Show hidden. Select a row or click its shape. The canvas footer displays coordinates, object count and the time spent in the most recent SVG reconstruction.

3 · Programmatic constructions

Type in the top-left input and press Enter. Names are case-sensitive, while construction keywords are not. The following commands are supported:

A = (0, 0)
B = (4, 2)
C = (-1.2e-2, 3)
D = (4, 4)
Segment(A, B)
Arrow(A, C)
Line(A, B)
Circle(A, B)
Ellipse(A, D)
Rectangle(A, B)
Polygon(A, B, C)
Polyline(A, B, C)
Bezier(A, B, C, D)
Angle(A, B, C)
RegularPolygon(A, B, 6)
Midpoint(A, B)
f(x) = sin(x) + x^2/4
X = Node(0, 0, "X")
Y = Node(3, 0, "Y")
Morphism(X, Y, "f")

Use ordinary names such as A or P_1 only where the current grammar accepts them: names must match [A-Za-z][A-Za-z0-9_]* in named assignments. Command argument positions refer to previously created named points (including midpoints); a morphism instead requires two named diagram nodes. The Node/Morphism command labels must use simple double-quoted text without embedded double quotes or backslashes. Complex TeX labels can be edited afterward in Properties or brought in by tikz-cd import.

The expression parser supports arithmetic + - * / ^, parentheses, x, pi, e, numerical literals (including scientific notation), and sin cos tan asin acos atan sqrt abs log ln exp floor ceil. Functions such as f(x)=1/x are plotted by screen sampling, not by exact symbolic analysis. Multiplication must be explicit (2*x, not 2x). The parser does not execute JavaScript. General implicit curves, numerical ODE/PDE solvers, symbolic algebra, arbitrary scripts, surface parametrizations and complex functions are not present.

4 · Live dependencies, object editing, locking and ordering

Shapes reference stable object IDs, not copies of point coordinates. If you move A, a segment Segment(A,B), circle Circle(A,B), and Midpoint(A,B) update immediately. Morphisms likewise follow diagram nodes. You may rename objects, set point/node/text coordinates, edit text, function expressions, stroke color, line width, opacity, node/polygon/ellipse fill, morphism bend and label side, and font size where meaningful.

After an invalid Properties edit, the previous successfully committed value is restored. You can immediately correct another field without a stale-editor error; for example, a rejected 101-sided polygon must not reset a previously accepted 9-sided value. Old controls from a different opened or undone project remain invalid.

For live rectangles, select either defining anchor to adjust the shape. Earlier files representing rectangles as four-point polygons retain their original semantics and are not silently converted. Valid successive property edits do not rebuild a currently focused input; a rejected edit restores the saved value and is undo-safe.

Locked prevents direct dragging, property edits and deletion of that object. If deleting a parent would delete a locked dependent, the deletion is rejected until the dependent is unlocked. A locked dependent may still follow its parent when that parent moves, because locking does not freeze mathematical dependencies. Hiding an object affects its rendering and most exports but does not remove it from the dependency graph.

Live-geometry movement protection (Cut 08): Moving a point/node by cursor or coordinate field rejects changes that would newly collapse a previously valid segment, line, radius-defined circle, regular polygon, rectangle dimension, angle ray, adjacent polygon edge or semantic morphism. On rejection the coordinate and whole scene are restored, without adding an undo step. This is a local degeneracy guard, not a general angle, distance or tangency constraint solver. Existing imported degenerate v1 geometry remains supported; moving unrelated objects is allowed.

Deleting an anchor removes every transitively dependent object. Undo restores the entire deletion. Bring forward and Send backward shift z-order one step. Dragging an individual point/node/text creates one undo record per completed gesture; a canceled drag reverts. Clicking to select an off-grid point does not snap or relocate it; moving beyond the 3-pixel drag threshold permits drag-and-snap. The final pointer-up coordinate is captured even if the browser sends no final pointermove. Group translation, multiple selections and direct manipulations of every path control are not yet implemented.

5 · Presets and detailed settings

Built-in presets are General, Olympiad geometry, Research diagram, Analysis / plots, Free illustration and Commutative diagrams. A preset adjusts future-object defaults, grid, snap, correction, axes and visible toolkits, not the styles of pre-existing objects. The four Visible toolkits toggles (Basic, Geometry, Illustration, Diagrams) may be modified independently. Changing any setting can turn the preset indicator into Custom; custom combinations remain in the saved JSON project, but naming/saving reusable custom presets is not yet implemented.

  • Regular polygon sides: select an integer from 3 to 100 before using the Regular polygon tool; each polygon also has an editable own side count in Properties. The center and first vertex remain live references. Choosing identical points is rejected rather than silently drawing an invisible shape.
  • Correction: Off uses raw sampled strokes; Gentle, Medium and Strong respectively increase smoothing and simplification. These controls apply before drawing: the selected correction is visible as a live draft while you drag, and finishing a freehand path commits that same correction. An interrupted/Escape-canceled stroke has no document object. A later change to Correction does not retroactively redraw the existing path. It does not recognize circles, equal lengths, tangencies or symmetry.
  • Grid snapping: Snap interval accepts 0.000001 to 1000 mathematical units; values below this range are rejected to prevent numeric overflow. The visual grid lines may be coarsened during zoom. Snap to existing visible, nontransparent points uses a near-pointer screen radius and creates shared mathematical references for new constructions. Anchors are resolved against a pre-gesture snapshot before adding new points, so nearby endpoints of a newly drawn short segment do not silently collapse into the same ID. Toggle either behavior independently. Freehand records raw cursor motion before correction.
  • Grid / axes / point labels: grid and axes are editor guides unless explicitly included in exported SVG/raster output. The page-frame guide is always editor-only. Point labels remain exportable illustration content. If the Basic toolkit is disabled, Move and Pan remain available, while the Point tool is hidden. The show-label toggle affects ordinary geometric points and their TikZ export, not text objects or diagram node labels.
  • New-object style: stroke, fill, width, point size and opacity. These are defaults; select an object on the left to edit its existing appearance. Newly created point and midpoint objects receive an editable individual Point radius property. Changing the global default affects future points; TikZ point radius now has a stable 0.75pt/px conversion independent of zoom. Historical v1 points without a per-point radius continue to use the document-wide default for compatibility. Point radius affects SVG and basic TikZ size, but publication font/scale parity is not certified.
  • Page and export controls: Infinite canvas, A4 landscape guide or Letter landscape guide. Export area selects the full current viewport or the centered page-frame crop; page-only export is disabled for an infinite canvas. Include grid and axes in image exports is OFF by default, so mathematical working grids do not accidentally appear in a paper figure. Turn it on to produce graph-paper illustrations. The page guide itself never exports. Transparent SVG / PNG / WebP (Cut 18) removes the exported image background while keeping the editor canvas opaque. JPEG is disabled when selected, because it cannot carry alpha; turn this off to enable JPEG again. This option is saved with the project, defaults OFF for old v1 files, and can be undone. Semantic arrow-label halos are removed from transparent exports. Raster resolution supports 1×, 2× (default), 3× or 4×, subject to a 36-million-pixel cap and maximum side length of 16,384 pixels. These settings are saved in JSON v1, with backward-compatible defaults. The frame preserves aspect ratio but does not encode physical millimeter/inch dimensions, bleed or calibrated DPI.
  • Theme: Light and dark UI themes. The project background is independent of the theme.

6 · Semantic diagrams and restricted tikz-cd interchange

Create nodes and morphisms with right-hand tools or Node and Morphism commands. Drag a node and attached morphisms move with it. Edit arrow labels, label-side swap and bend in Properties. The rendering is a native SVG diagram, not TeX typesetting: a label such as \alpha appears literally in the browser.

Click Import TeX, paste a single \begin{tikzcd} ... \end{tikzcd} environment, and confirm project replacement. The supported subset has a rectangular &/\\ matrix of nonempty node labels, with direct \arrow[r, "f"], \arrow[dd, "g"'], and directions composed of r,l,u,d. The maximum is 40 rows × 40 columns. Each arrow must point to an existing labeled node. Unsupported arrow options, nested environments, bend declarations, style options or malformed syntax cause a visible error; no TeX is executed.

\begin{tikzcd}
A \arrow[r, "f"] & B \\
C \arrow[u, "g"'] & D
\end{tikzcd}

SVG XML label safety (Cut 08): Names and text labels reject XML 1.0 forbidden control characters and unpaired UTF-16 surrogates. Valid Unicode mathematics and emoji remain available for SVG/PNG; non-ASCII labels still disable plain pdfLaTeX TikZ as documented. The JSON schema rules out C0 controls, but the runtime enforces full Unicode scalar validity where schema engines differ.

The tikz-cd export option is enabled only when all visible scene objects are diagram nodes/morphisms, endpoints remain visible, morphisms are unbent, labels contain no unsupported quotes/newlines, and positions can form a unique grid. It preserves labels and directed incidence. A TeX \& is correctly treated as text inside a node label, not a cell boundary. The exporter reimports its own output and compares the semantic node/arrow graph: if embedded labels could be interpreted as extra cells, arrows or unsupported syntax, tikz-cd export is disabled rather than silently corrupting the diagram. The importer rejects multiple labels on the same arrow rather than silently discarding one. The restricted subset permits escaped \& inside labels but rejects ambiguous raw ampersands and embedded arrow commands that would change graph semantics. It does not preserve arbitrary pixel coordinates, colors, custom arrow shapes, font settings or current panel layout. For those, export SVG or the native JSON project. Mixed geometry plus diagrams disables this export rather than discarding non-diagram objects.

7 · Native JSON, autosave and undo/redo

Use Save to download the lossless editable mathillustrator.json file. Open accepts version-1 project JSON of up to 12 MB, validates object types, coordinates, styles, IDs, uniqueness, dependency targets, cycles and expressions, then asks before replacing the current document. Existing Cut-00, Cut-01, Cut-02 and Cut-03 and Cut-04 version-1 projects open with defaults for newly added options, including a six-sided regular-polygon default, guides OFF for image export and raster resolution 2×. No JSON version number change was required. Do not hand-edit object IDs or parent references casually.

Concurrent file-read safety: if the current document changes while an Open JSON file is being read, the pending import is canceled instead of overwriting the intervening edits. Open the file again when ready. This checks changes to the document, not view-only panning or the selected tool. Import/export dialogs can be closed with Escape and return keyboard focus to their launcher; drawing-wide delete and undo shortcuts are suspended while a dialog is open.

Browser autosave is debounced and depends on localStorage availability/quota. It is not a permanent, multi-device backup. If the existing saved project is malformed, the editor starts an empty recovery view but quarantines the original localStorage bytes, pauses autosave and asks you to choose Keep this tab explicitly before replacing them. Download a JSON backup of the recovery view when relevant; the damaged original is not silently repaired. If another tab stores the exact same document bytes, the editor synchronizes its saved token without a false conflict. If another tab updates the project differently, this tab pauses autosave and presents an explicit conflict banner: download the current tab’s JSON, then choose whether to load the other tab or deliberately keep this tab. Invalid/corrupt external data is refused. Open two tabs only with this limitation in mind; offline and site-data-clearing behavior depend on the browser.

Undo/redo records up to 80 document snapshots in memory (with a 30 MiB older-history eviction cap), including edits, property changes, document import, new project, and completed drags. Pan, zoom, theme changes, selection and the currently active tool are not included. Reloading clears undo history. Ctrl/Cmd+Z undoes; Shift+Ctrl/Cmd+Z or Ctrl/Cmd+Y redoes. Delete/Backspace removes selected objects unless a text input has focus. Escape cancels a draft or active drag, restoring the original view when panning. Secondary pointers cannot hijack an existing drag or steal the active hover position. Detached controls from a replaced document cannot edit another document even when object IDs are reused.

9 · Exact limitations and troubleshooting

  • Advanced mathematical areas: general implicit curves, high-order differential geometry, curved manifolds, 3D meshes, Ricci-flow blow-ups, Möbius grids, generalized geometric constraints, group actions, category-theoretic diagram proofs, vector fields and animation timelines are not yet implemented.
  • Freehand: adjustable smoothing is not handwriting-to-geometry recognition; no independent Bézier handle GUI, curve fitting to prescribed tangencies, boolean operations, vector masking or intelligent equal spacing yet.
  • LaTeX: tikz-cd import is a documented narrow subset, not an arbitrary TeX/TikZ parser. Arbitrary TeX is never evaluated by this app. TeX source in labels is displayed literally on canvas.
  • Plots: explicit y=f(x) plots now use bounded adaptive subdivision with gaps around detected poles, nonfinite values and unresolved severe curvature. This improves discontinuity handling but is not a mathematical proof that every singularity, removable discontinuity or oscillatory spike is found. No implicit curves or differential equation solver.
  • Cut09 stale export cancellation: PNG/JPEG/WebP rasterization happens asynchronously. If you edit the project, pan/zoom, resize the viewport or dismiss the export dialog while the image is encoding, the pending export is canceled with a visible message rather than saving stale art. A stuck SVG decode or image encoder fails with a message after 15 seconds per stage. Reopen Export and try again; use SVG or native JSON for a stable vector/editable backup.
  • Cut09 interrupted drawing: if the browser window loses focus or the document becomes hidden during a drag, the unfinished point/pan/freehand gesture is rolled back rather than committed. Existing history and saved JSON are preserved.
  • Export: no native PDF/Asymptote/animated output, physical page scale or scientifically exact plot topology. The raster resolution setting affects images only, not TikZ or the JSON project. WebP/JPEG depend on browser APIs.
  • Mobile narrow screens: the panels collapse into narrow rails and can be opened using the arrow buttons; supported in isolated Chromium. Touchscreen gesture behavior and Safari/Firefox remain unverified.
  • Performance: full SVG scene rebuilding remains the design; in three Cut 05 isolated Chromium observations, 3,000 plain point objects rebuilt in 21.8, 41.9 and 34.2ms (not a 60 FPS guarantee or cross-device benchmark); dense freehand, text, diagrams and less powerful machines can be slower. The app has no GPU rendering yet. Dense explicit function plots can also take time; the sampler caps subdivision and does not silently delegate calculations to a server.
  • Input anomalies: malformed project JSON, duplicated IDs/names, unsafe object ID magnitudes, cycles, nonfinite coordinates, unsupported formulas and unknown TeX commands are rejected visibly. New zero-length segments, arrows, lines, circles, rectangles and degenerate-angle rays are rejected before insertion. Historical flattened ellipses remain compatible and render as line segments in SVG/TikZ. If a project cannot be opened, preserve the original JSON; do not overwrite it after an import error.
  • Large object list: with thousands of objects, the left sidebar uses a virtualized scrolling list, showing only nearby rows in the DOM. Filtering finds any model object, including those not currently drawn in the list window. Search substrings can match multiple names; scroll the filtered results as needed. Full screen-reader and keyboard-only navigation across virtual rows remains unverified.
  • SVG point selection: a point under a polygon is picked geometrically when within its hit radius. Point hit disks are not drawn as separate invisible SVG elements, reducing DOM load. Rendering culls far-offscreen points; they still exist in JSON and reappear upon panning or fitting.
  • Touch/accessibility: basic pointer and keyboard operation works; rich touchscreen gestures, complete keyboard-only drawing, screen-reader diagram comprehension and comprehensive cross-browser accessibility remain to be tested.

10 · Cut 04 subtle-case guide

  • Drawing precision: a freehand stroke is previewed while dragging with the right-panel Correction mode applied. Clicking an unsnapped point merely selects it; dragging farther than three screen pixels can invoke configured snapping. Canceled strokes, pans and point moves must not commit partial results.
  • Stale UI: after New, Open, Undo or Import, old property and object controls no longer refer to the active document. Reselect the intended object before changing properties. This prevents same-ID corruption on replaced projects.
  • Semantic TeX interchange: use \& within a literal TeX label, not raw &. If a cell label could be confused with an arrow command or row/column separator, the tikz-cd exporter is disabled. Use native JSON to retain arbitrary exact text, appearance and editing.
  • Transparency: an object with opacity zero remains in JSON and participates in dependencies, but invisible point labels and hit targets must not obstruct the editor; SVG/TikZ labels carry the matching opacity.
  • Performance & verification: live freehand preview adds rendering work; large scenes can be slow. Regression assertions use isolated Chromium rather than deployment, and TeX compilation proves only compilation for tested examples, not full semantic or visual parity.

11 · Cut 05 subtle-case guide

  • Exporting multiple illustrations: Cut 05 uses self-contained arrowhead polygons instead of IDs shared across separately embedded SVG figures. Arrows may still differ slightly in scale from TikZ; inspect final PDF output.
  • Point selection behind shapes: selecting or dragging a visible point works through overlapping fills, with a nearest-point preference. A locked point can be selected but not moved; opacity-zero and hidden points do not intercept clicks.
  • Large lists and views: only a limited window of object rows is present in the DOM; scroll or search to access others. Offscreen point culling is a display optimization only: saving, Fit, geometric references and export of the *current* viewport remain document-based. A point whose label could intersect the viewport is retained.
  • Reliability: changing a color, undoing, replacing the project, scrolling after hiding entries and applying a filtered edit are checked for stale controls. A failed import should not alter existing objects. If a storage-conflict banner appears, download JSON before choosing a version.
  • Benchmark provenance: 3,000-point scene rebuild observations (21.8/41.9/34.2 ms) came from three isolated headless Chromium runs, not an instrumented user device, not a frame-time percentile, and not a promise of 60 FPS.

Cut 06 (v0.7) — reliable short constructions and export

Close vertices: If you draw a very short segment, the first endpoint created by that gesture is not allowed to capture the second through automatic snapping. Both vertices are first matched against anchors already in the drawing; remaining vertices are inserted only afterwards. This also applies to regular polygons and free polyline/polygon completion. Clicking the same existing anchor twice still reports a rejected degenerate construction. Fully transparent or hidden points cannot automatically capture cursor snapping, though they remain in saved mathematical dependencies.

Very small snap intervals: The minimum supported interval is 0.000001 world units. Lower values can overflow the coordinate quotient in floating-point arithmetic. The editor now rejects them explicitly. Increasing snap granularity beyond the supported minimum requires a future higher-precision coordinate engine.

Toolkit visibility: The Basic module can hide its Point tool, but Move/Pan remain reachable. Undo restores the previous module setting. Use the right panel to adjust grid and anchor snapping before drawing.

TikZ: A hidden unsupported graph does not prevent exporting visible compatible geometry. Exporting the same model twice at different canvas zoom levels now yields identical TikZ source. Line/point thickness uses 0.75 pt per CSS pixel. Angles and text are still approximate publication depictions; world coordinates are not rescaled to paper and mathematical TeX source is not interpreted from canvas text.

Saving and concurrency: Normal autosaves use the Web Locks API for exclusive same-origin writes where the browser supports it, while checking the stored version before writing. Browsers without Web Locks and last-chance unload writes cannot guarantee atomic multi-tab changes. A detected conflict pauses autosave; choose to load the other tab or explicitly overwrite only after downloading a JSON backup. Do not assume cloud sync, automatic merge or durable crash recovery.

JSON compatibility: v1 remains supported; invalid projects claiming both an infinite canvas and page-only export are rejected rather than silently exported using another region.

Cut 10 (v0.11) — diagram edges, focused editing and dense plots

Diagram morphisms: Arrows now stop near the visible boundaries of rectangular node boxes rather than passing into their centers. Node dimensions are estimated from font size and Unicode characters, not exact font/TeX glyph metrics. On tightly packed diagrams the arrow's cosmetic padding contracts. If node boxes actually overlap at the current zoom, the visible arrow may temporarily disappear rather than reverse its direction. The morphism remains in the left object list and native JSON: move its nodes apart or zoom in to restore the visible connection. The morphism's bend and label remain editable. The semantic tikz-cd graph is independent of this SVG layout approximation; PDF/TikZ appearance is not guaranteed identical.

Infinite lines: A programmatic Line(A,B) extends indefinitely in its mathematical definition, but the editor clips its visible SVG path to the current viewport. A line entirely offscreen is not painted. Fit, native JSON and its source anchors remain unchanged. TikZ is still a bounded publication depiction rather than a literal infinite curve.

Large function drawings: The editor caches a bounded number of sampled visible plot paths for unchanged function expressions and camera settings. Changing an expression, viewport center, zoom or canvas size automatically resamples. This makes selection and property edits less costly in static plot-heavy scenes, but does not guarantee 60 FPS or certify discontinuities, roots, poles or exact topology. Extreme graph densities and other shapes still require more renderer optimization.

Keyboard and overlays: Focus an object-list row, then use ArrowUp/ArrowDown or Home/End to navigate visible, filtered objects. Enter/Space selects. The export selector and TeX import dialog keep Tab navigation inside their open overlays, Escape restores the launcher, and the export selector has a clickable backdrop that closes it without editing the canvas. During an open export selector, the background Save/New buttons are intentionally unavailable; dismiss the selector first. Screen-reader behavior, true modal inertness in all browsers and physical touch are not certified.

Exports and losses: For editing, save the lossless v1 JSON project. SVG has zoom/page-dependent appearance; normal TikZ is zoom-independent but not an exact visual conversion of node boxes, font metrics or curvature. When a format is unsupported or unsafe for the current scene, its button remains unavailable rather than performing a hidden fallback. Current unsupported formats include native PDF, Asymptote and animation.

Cut 11 (v0.12) — labels, snapping, plot quality and publication boundaries

Long diagram labels: A diagram node now displays text across multiple centered lines when necessary, and explicit line breaks are preserved. The original label is retained exactly in JSON, as are its live morphism references. Arrows clip to the same estimated bounding box used by the node rectangle. This is approximate browser text layout, not TeX math rendering, collision-free label placement or a guarantee of identical font metrics across devices. If the node text needs automatic browser wrapping, ordinary TikZ/PGF geometric export is disabled rather than silently producing different text layout; use SVG or native JSON. The restricted semantic tikz-cd interchange describes the graph, not the exact on-screen positions.

Fit and small numbers: Fit now reserves additional pixel space for node rectangles, point names and text labels, rather than fitting solely their world-coordinate anchors. A warning appears if the viewport is too small for a fixed-size label. Infinite lines and graphs cannot be completely framed by a finite rectangle. The left list and pointer coordinate display use adaptive precision: very small nonzero values are printed in scientific notation instead of appearing as 0.000. This changes display only, not coordinate storage or numerical precision.

Fast anchor snapping: Point and derived-midpoint selection uses a lazy screen-space lookup index; hidden and fully transparent objects do not snap or intercept clicks. Locked visible anchors remain mathematically referenceable. The index updates after document changes, undo/import, pan/zoom and canvas resize. Equal-distance snapping retains earlier-created-anchor priority; exactly overlapped point picking favors the top layer. The new-vertex snapshot rule from Cut06 still prevents a point created earlier in the same drawing gesture from capturing the next endpoint. This is a pointer lookup acceleration, not full-scene incremental drawing or GPU rendering.

Function plotting controls: Set Plot detail in the right panel to Fast (lower cost), Balanced (default), or Detailed (higher cost). The Analysis / plots preset defaults to Detailed. Every mode samples an explicit real-valued y=f(x) expression on the current viewport; none mathematically proves the absence of hidden spikes, removable holes, close poles or high-frequency oscillations. Sampling stops at an 80,000-evaluation ceiling. If that limit is reached, the footer identifies a PLOT LIMIT and SVG/raster image export is disabled for the incomplete view, while native editable JSON remains available. Narrow the view, simplify the function, or lower detail to continue. A higher quality may cost noticeably more CPU. Old v1 files without plotQuality open as Balanced; unknown quality values are rejected, never silently converted.

Safety and limitations: Imported or typed node labels are SVG text, never browser HTML; no JavaScript, raw TeX macro execution or external dependency is permitted by the editor. Complex mathematical typography, precise browser/TeX alignment, continuous curve topology, physical paper DPI, live 3D, Möbius and Ricci-flow models are still unsupported. A functioning localhost/deployed GitHub Pages test, real multiple-tab locking, non-Chromium fonts, physical touchscreen and screen-reader testing remain outstanding. For future editing and recovery, always keep native JSON.

Cut 12 (v0.13) — visible-scene Fit, background interruption and complex construction speed

Fit to visible artwork: Fully transparent objects still exist in the left panel, can remain dependencies, and remain in your editable JSON, but they no longer pull the Fit camera away from visible geometry. Diagram arrows attached to hidden or transparent nodes also do not affect Fit, because those arrows are not actually displayed. If all geometry is invisible, Fit resets to a default view. Fit still uses approximate pixel dimensions for text and cannot fully frame mathematically infinite curves.

Switching tabs while drawing: When the browser reports the document becoming hidden, an unfinished point drag or canvas pan is canceled and restored to its starting state. A completed edit is unchanged. This prevents incomplete pointer gestures from being mistaken for finished work when a tab is hidden. It is not a guarantee against browser crashes, power loss, failed local storage, or an operating-system suspend occurring before an event can run. Save editable JSON backups for important figures.

Many vertices: Completing a polygon, polyline, Bézier or another anchored construction now uses the same screen-space anchor index used for pointer selection. This reduces repeated scanning for large projects. The index examines only the anchors that existed before this gesture: endpoints created earlier in the same gesture cannot accidentally capture later ones. The 12-pixel snap threshold and earlier-created anchor priority remain unchanged in the tested scenarios. Large SVG redraws, complex mixed scenes and thousands of actual mouse clicks may still be slow; this is not a universal frame-rate improvement.

Verification boundaries: The new lifecycle tests synthesize a hidden-document event in isolated Chromium. The performance comparison is a synthetic 6,000-anchor/1,200-vertex batch and excludes rendering. The 152-control matrix and named-function inventory document progressive verification rather than claiming that every possible interaction has been fully certified. Published-site behavior, non-Chromium browsers, real touchscreen interaction, complete accessibility and true atomic multi-tab storage remain unverified.

Cut 13 (v0.14) — precise drawing presets and safer Settings

Drawing presets: The right-side selector now describes a Drawing preset, not the whole project. Choosing General, Olympiad geometry, Research diagram, Analysis / plots, Free illustration or Commutative diagrams restores the preset's drawing styles and available toolkits as well as common construction defaults: snap to existing anchors on, point labels on and regular polygons with six sides. If you change these drawing settings afterward, the selector displays Custom; this is a status, not a named reusable preset you can select. The page frame, export resolution/area/guides and theme are intentionally independent of a drawing preset and are not reset by choosing one. Existing geometry is not restyled.

New point size versus existing points: Changes to New object style → Point size apply to points created afterward. Modern objects have an explicit radius. Some older JSON projects did not store an individual radius, inheriting the current default. When you first change that default, the editor writes the older objects' previous size as an explicit per-object radius so their current appearance does not unexpectedly change. This happens only when the default actually changes, not merely by importing older JSON; Undo can restore the earlier project state. The project format remains version 1.

Keyboard safety: Delete/Backspace deletes selected geometry only when drawing/document or an object-list row is the keyboard context. With focus on Zoom, Save and other controls, the same keys must not delete an unrelated selected object. You can still delete deliberately using Delete selected or the object Properties button; edit fields keep normal text-key behavior.

Export settings performance: Export area, optional exported guides, and raster resolution save normally and participate in Undo/Redo, but adjusting them no longer needlessly rebuilds the visible SVG. These controls affect the next export rather than the displayed editor. Grid/axes, page, background, plot detail and actual object changes still require a redraw. This is a targeted large-scene optimization, not an overall 60 FPS guarantee.

Testing and limitations: The above behavior is covered by isolated Chromium and Node regressions, not by verified hosted-site testing, Firefox/Safari, mobile pen hardware, screen-reader navigation or genuine simultaneous-tab locking. Native JSON is still the safest editable backup.

Cut 14 (v0.15) — interrupted constructions, keyboard input and saving failures

Unfinished constructions: A segment awaiting its second endpoint, a polygon or polyline awaiting further vertices, and a diagram morphism awaiting its target are temporary sketches only. Choosing New, opening a JSON project, importing a semantic diagram, switching to another browser tab or losing window focus cancels those unfinished steps. Re-select the tool and start again after returning; completed geometry and saved JSON are not discarded by this rule. This prevents invisible old endpoints from unexpectedly appearing in a new project.

Import races: When a native JSON file is still being read, changing or replacing the current project cancels that import. This includes selecting New even when both projects look identically empty. Failed/canceled imports show a message and do not silently overwrite more recent work.

IME and shortcuts: Global Delete/Backspace, Undo/Redo and Escape shortcuts are ignored while a keyboard text-composition session is underway. The semantic tikz-cd import dialog also stays open if the composition system sends Escape while forming a character; ordinary Escape outside composition still closes it. Real device/OS IME behavior has not been exhaustively tested.

Changing zoom while dragging: Zoom buttons, Reset, Fit and the mouse wheel first cancel any unfinished point move or pan, avoiding accidental movement caused by changing coordinate systems during a drag. Your previous completed changes and their Undo history are preserved. If a gesture is interrupted, start it again after zooming.

Saving when browser storage is full or restricted: The editor shows Not saved locally when an autosave write fails; this must not be interpreted as a successful save. Use the Save button to download a full editable mathillustrator.json project before closing the page. Once storage is available again, a subsequent edit will retry autosave. A simulated storage failure/recovery test passed, but real storage quota behavior, private browsing, tab crashes and true same-origin concurrent saves remain unverified.

Verification scope: The new cases were tested in isolated Chromium with synthetic visibility and IME events and a controlled localStorage double. They are not a substitute for deployed-site, Firefox/Safari, real touchscreen, physical IME or simultaneous-tab tests. Mathematical object semantics and the editable project schema remain at version 1.

Cut 15 (v0.16) — Touch drawing, mobile controls and wheel behavior

Mouse vs pen vs finger: Mouse and pen clicks use their original tools. On a touchscreen, Point, Segment, Polygon, Diagram Node and other click-to-construct tools now wait until the finger lifts before accepting the point or vertex. Moving your finger more than 10 CSS pixels or lifting outside the canvas cancels that pending tap. This avoids accidental geometry when a second finger begins a multi-touch gesture.

Two fingers: The current editor does not provide pinch-to-zoom or palm-rejection. A second touch on the canvas or tool panels instead cancels an unfinished gesture or click-by-click construction, rolls back an uncommitted pan or drag, and blocks further touch drawing until all fingers are released. After a canceled gesture, start the construction again. Use the +, − and Fit buttons for zooming, or an ordinary mouse wheel.

Stylus and wheel: A pen pan uses its final lift position even if no intermediate movement event was delivered. A wheel event specified in pixel, line or page units is interpreted consistently using a 16-pixel line approximation and one-canvas-height page unit; zoom limits still apply. This conversion does not guarantee identical sensitivity across operating systems or browsers.

Phone layouts: The top commands wrap instead of hiding Export off to the right; the drawing canvas and drawers follow the measured toolbar height. Finger-sized tool buttons become larger where the browser reports a coarse pointer. The mode description is hidden at very narrow widths but remains available through the tool buttons and accessible canvas label. The object and tool drawers continue to open from the side rails.

Exports after touch: Native PNG, JPEG, WebP, SVG and editable JSON capabilities are unchanged; a new emulated Chromium touch-to-PNG check passes. No physical iPhone/Android/iPad test, Safari/Firefox pixel-parity check or native PDF export is claimed.

Data safety and remaining risks: Project autosave and JSON backup follow the existing Cut14 policy. The new deferred-lock tests use synthetic storage and locks, not genuine concurrent browser tabs. Phone hardware, touch gestures with more than two fingers, palm rejection, screen-reader navigation, browser storage quota and power-loss recovery remain unverified.

Cut 16 (v0.17) — Autosave recovery and concurrent-tab warnings

Retry a failed local backup: If a browser quota error or storage denial interrupts autosave, the footer says Not saved locally and displays Retry local save. You can free browser storage or change permissions, then click Retry without modifying the illustration. Until the status confirms success, use the header's Save button to download native JSON to a safe location. Closing or crashing a tab can otherwise lose unsaved changes.

Cross-tab behavior: The app compares complete project snapshots before each save. When another tab has already saved the exact same JSON, that is a harmless synchronization, not a conflict. When its content differs, autosave pauses and displays a warning. Download your current tab as JSON before choosing Load other tab or explicitly Keep this tab. The labels distinguish corrupted startup data from a later conflict. If another tab clears site storage, your open drawing remains in memory but saving pauses until you decide which state to keep.

What is and is not guaranteed: Normal saving uses Web Locks if supported, but browsers without Web Locks and the final page-unload attempt have no atomic-save guarantee. Storage notifications may be delayed; the editor now checks actual current saved bytes rather than trusting an obsolete notification. Neither these checks nor the retry button are cloud sync, crash recovery, automatic merge, or proof of durable simultaneous-tab writes on every browser. The new verification uses a controlled storage double inside isolated Chromium; real two-tab browser-origin tests remain blocked by this environment.

Cut 17 (v0.18) — Transparent objects and offscreen rendering

Opacity zero means truly invisible: an object with opacity 0 is retained in the object list, native JSON, geometric construction relationships and undo history but is not rendered to the SVG or its SVG-based image exports. Transparent functions are not needlessly sampled. This can also reduce the size and rendering cost of a figure. Restore a hidden-by-opacity object by selecting it in the object list and raising its Opacity under Properties.

Semantic arrow export: SVG hides a morphism whose defining node is invisible. TikZ therefore disables publication export when an otherwise visible morphism connects to an opacity-zero node; it does not silently invent a visible arrow. Fully transparent morphisms and point labels are omitted from TikZ. To export a complete diagram, reveal its relevant nodes or remove the unsupported visible morphism; native JSON always remains available.

Large-scene drawing: shapes fully outside the visible canvas are conservatively omitted from the current SVG repaint and image viewport export. They are not deleted from the editable project; pan or zoom to see them again. Segments crossing the viewport remain drawn even if both endpoints are outside it. Strokes near the frame edge are padded to avoid clipping thick lines. Some text, infinite lines and graph paths remain expensive and are not aggressively culled because an approximate bounding box might misrepresent them.

Performance limits: On one isolated Chromium mixed scene, median rebuild time improved from 20.45 ms to 6.30 ms with offscreen SVG culling (12 samples each). This is a scene-specific measurement, not a promise of smooth animation, browser consistency, or 60 FPS at 10,000 objects. SVG/PDF/TikZ still differ in label metrics, fonts, color mixing and semantic capabilities; verify the final publication in its target application.

Cut 19 (v0.20) — exact mathematical text and responsive large diagrams

Multiline properties: Select a Text, Diagram Node or Morphism in the left object list. Under Properties, type into the multiline Text / label or Arrow label field. Press Enter to create an intentional new line and click outside to commit. Undo/redo, autosave and native JSON retain the original string, including repeated spaces and line breaks. A single-line label remains a single-line SVG object.

Automatic node wrapping: Long node labels may be visually wrapped within an estimated 340-pixel-wide box. Unlike earlier versions, even spaces at a wrap boundary are preserved, since whitespace can matter in mathematics. The SVG renderer uses explicit positioned text spans for intentional newlines in Text and Morphism labels. The project never silently trims your label. Automatic wrapping, font metrics, arrow-label positions and collision handling are still approximate; inspect dense figures before publication, especially on other browsers or with unavailable fonts.

Export limitations: Unsupported multiline and spacing-sensitive labels still disable restricted pdfLaTeX TikZ rather than being flattened or reinterpreted. SVG and the editable JSON remain available, subject to target font metrics. Semantic tikz-cd remains a separate restricted graph exporter, not a WYSIWYG text-layout conversion.

Responsiveness: Text and diagram-node objects entirely outside the viewport may be omitted from the current SVG to reduce DOM work. They remain visible in the left object list, searchable, editable, and fully saved in JSON. Panning back redraws them. Even when both endpoint node boxes are offscreen, a connecting morphism crossing the viewport is still drawn. If a label lies very close to the edge, its conservatively estimated text bounds try to avoid accidental clipping; font-exact culling and collision-free layout are not guaranteed. A synthetic 2,520-label scene (2,400 offscreen) saw median SVG rebuilding drop from 43.80 to 8.75 ms in isolated Chromium, not a general frame-rate guarantee.

Cut 20 (v0.21) — selecting overlapping objects and point-label placement

Selecting crowded objects: In Move mode, a normal click still selects the nearest visible point, which can be dragged. When several objects occupy the same screen location, hold Ctrl and click repeatedly (use Command on macOS) to cycle through selectable points and other visible SVG objects at that location. This does not move the geometry. Shift-drag and Alt-drag still pan. Hidden objects cannot be selected from the canvas but remain available in the left object list. This is an explicit gesture, so normal clicks do not suddenly select a different coincident anchor each time. Results depend on browser hit-testing for non-point SVG elements; use the object list if another browser behaves differently.

Reducing overlapping point names: In the right panel under Correction & snapping, set Point label placement to Avoid nearby overlaps. It tries six screen-space positions around each visible point and avoids point markers, previously placed names, and obvious canvas-edge clipping. The default Standard exactly retains the previous right-above placement, including when loading old project-v1 files. Names, coordinates, and semantic object references are never modified. You may undo/redo the setting, and choosing a named preset restores Standard. If there is insufficient empty space or a font is unusually wide, names may still overlap. This does not yet resolve label collisions with arbitrary text, nodes, or morphism paths, and it does not change the diagram-node wrapping system.

Publication/export restrictions: SVG and supported PNG/WebP exports reproduce the current placement for the exported view. Change back to Standard, hide point labels, or use SVG/PNG/WebP/JSON. This is deliberate, not a failure of your data. Auto placement is computationally more expensive, particularly with thousands of visible points; the mode remains opt-in. Layout is cached for unchanged scenes, but recalculated during a point drag to keep labels attached to the moving object. The historical numeric performance record (inside docs/history/release-history.zip, path docs/quality/cut20-performance.json) is a single isolated Chromium workload, not an FPS guarantee.

Limitations: At Cut20 there were no per-morphism label offsets or arrow detours; Cut21 adds limited, opt-in versions. Exact text shaping, collision-free guarantee, global optimal routing and cross-browser visual parity remain unsupported. Cut 21 (v0.22) — semantic diagram routing and editable morphism labels

When to use it: Select a Morphism in the left object list. Its Properties now offer Arrow routing: Direct / curved (legacy) preserves the original arrow and bend behavior, while Avoid diagram nodes (two-turn) attempts to route around other visible diagram-node boxes. New and imported v1 arrows retain Direct unless you explicitly choose Avoid. This is a best-effort display feature and never changes the mathematical source/target node references.

When automatic routing is impossible: The editor draws an amber dashed arrow with a descriptive SVG title instead of pretending the obstruction was removed. In a heavily packed diagram, manually separate nodes, enlarge the workspace or use Direct with a custom bend. If the endpoint node boxes overlap so closely no positive arrow shaft fits, the arrow is temporarily suppressed as in previous versions; its semantic object remains in the left panel.

Manual arrow-label placement: Under Properties, edit Label position on arrow (0.05–0.95), Label distance (px) (0–200), and Label shift X/Y (px) (−300 to +300). The existing Swap label side flips the perpendicular offset. The position is measured along the actual displayed curve or polyline, not in world-coordinate units. All changes support undo/redo and native JSON; the default values 0.5, 17, 0, 0 preserve the previous appearance. A label may still collide with an unrelated node, path or label; inspect final artwork manually.

Exports: SVG, PNG/WebP where supported, and the editable JSON project preserve this new screen-space layout for the exported view. TikZ/PGF is disabled for visible morphisms using Avoid routing or nondefault manual label values: the restricted conversion would otherwise silently change the figure. tikz-cd remains available for the documented restricted graph-only semantic interchange, not exact visual positions. Direct/legacy arrows without custom positions retain their previous TikZ capability subject to all other preflight checks.

Performance and limitations: Automatic detours cost additional computation and may vary as nodes are moved, shown/hidden, or zoomed. In one isolated 320-node/80-arrow Chromium SVG redraw benchmark, median times were 14.8 ms in Direct and 17.2 ms in Avoid mode; this does not establish 60 FPS or performance across devices. Corridors are limited to up to four two-turn candidates; there is no global graph-edge crossing solver, self-arrow routing, exact font metrics or collision-free guarantee. A detour or a large manual label shift may extend beyond the current viewport or the page export crop. Current Fit-to-illustration primarily frames mathematical objects and node boxes, not every detoured path or manually shifted label; zoom/pan or resize the page before publication. See the regression and raw-performance records for scope and provenance.

Cut 22 (v0.23) — drag arrow labels directly

Choose Move in the right panel and select a labeled diagram morphism, either by clicking its arrow or its left-panel object row. A small purple-outlined circular handle appears beside the text. Drag the handle to reposition the label in screen pixels while the semantic source and target nodes, curve and routed arrow stay unchanged. Release to commit one undoable move; use Undo to restore the previous position. The four existing numeric label controls remain available in Properties for exact adjustments and for users who cannot use the pointer.

Control and failure behavior: Moving less than 2 screen pixels is treated as a click, not a change, so an existing fractional offset is not rounded. Ctrl/Command-click continues to cycle overlapping objects, and Shift/Alt dragging remains canvas panning rather than a label edit.

Native JSON records only the same optional labelDx/labelDy fields available since Cut 21, so all previous version-1 projects remain compatible. Cut 23 (v0.24) — avoid collisions between diagram labels

How to enable: Select a Morphism in the left panel and check Avoid nearby nodes / labels (best effort) in Properties. The setting applies only to that arrow. The engine checks visible diagram-node rectangles and other visible morphism-label rectangles in screen pixels and tries nearby positions. Any label you have left in manual mode keeps its chosen position and takes priority over automatic labels. The mathematical arrow, source/target references, exact text, curve and node positions are never changed. Older v1 projects default to manual placement.

When there is no clear solution: A label remains visible, turns amber, and its SVG group is marked as an unresolved label collision. The layout does not delete or truncate the text, silently omit it or claim that the overlap has been corrected. Move nodes, zoom, enlarge the exported viewport, or reposition the label manually. This is a bounded candidate search, not global graph optimization; it does not check all arrow-path crossings or arbitrary point/text labels.

Drag-to-manual handoff: With Move selected, drag the purple label handle. The label switches from automatic to manual placement only after a genuine movement, preserving its displayed position and the normal one-step Undo history. Stationary clicks leave it automatic. Escape, pointer cancellation or focus loss restores the prior automatic setting and label location. The existing ±300 px manual shift limit still applies, so extreme displacements may be clamped. Numeric Properties remain a keyboard-accessible alternative.

Export and persistence: SVG/PNG/WebP retain the displayed positions for that specific viewport and zoom; native JSON saves only the boolean labelAvoid, not a frozen font-dependent offset. Because these automatic screen positions cannot be represented accurately by the limited TikZ/PGF converter, that export is disabled for visible labeled arrows with avoidance enabled. An arrow with an empty label has no visual placement to lose, so the flag alone does not disable TikZ. The restricted tikz-cd output still conveys semantic morphisms, not visual label placement. Browser fonts and page cropping can alter visual positions; preview your exported figure for publication. Performance with thousands of simultaneously visible labels is not guaranteed.

Cut 24 (v0.25) — reduce crossings between diagram arrows

How to enable: Select a diagram Morphism in the left object list. Under Properties → Arrow routing, select Reduce crossings (best effort). The original Direct / curved and Avoid diagram nodes choices remain available and retain their earlier behavior. The new mode is optional, per arrow, and saved in native JSON v1. It never rewires the source/target nodes, moves other objects, or alters your label text.

How the search works: At the current zoom, MathIllustrator considers visible arrows that appear earlier in object order, and checks whether the current arrow can take a short, node-clear two-turn detour with fewer interior arrow crossings. The chosen path may change after you hide/move another arrow, change zoom, or reorder your diagram. For dense graphs, the bounded search may be incomplete. It does not guarantee a globally minimal number of crossings, a planar drawing, precise overlap detection, or avoidance of all arrowheads and labels. An arrow sharing a node with another can still overlap it.

Unresolved state: If the supported corridors cannot fix a crossing, visible nodes block the path, or the 128-earlier-arrow / 8192-segment-pair safety ceiling is reached, the arrow appears dashed amber with a descriptive SVG tooltip. This is a warning, not an indication that the semantic morphism is invalid. You can manually move nodes, adjust the workspace, hide other arrows, or select Direct/Avoid nodes instead. The route computation never silently deletes geometry.

Export and interaction: SVG and supported PNG/WebP output render the chosen path for the exported view; the editable JSON project retains the routing preference and exact node references. A visible arrow using crossing-aware routing disables the limited TikZ/PGF visual export rather than pretending to reproduce its screen-pixel route. Semantic tikz-cd interchange is a separate graph representation and does not preserve visual crossings. Undo/Redo and label dragging remain supported. Before publication, inspect arrow crossings and cropping at the final output size, especially with long detours or different fonts.

Performance: Routing is limited and opt-in. In one isolated Chromium scene with 48 nodes and 80 arrows, median SVG rebuild time was 7.75 ms with Avoid nodes versus 7.90 ms with Reduce crossings. This is not a browser-wide speed guarantee; larger graphs, curved arrows and physical devices need separate measurements. The complete test provenance is in the Cut 24 quality report.

Cut 25 (v0.26) — consider earlier and later diagram arrows

Enable: Select a semantic morphism from the left object list. Under Properties → Arrow routing, choose Consider all visible arrows (max 48). This option is distinct from the earlier-only crossing reduction introduced in Cut 24. Old projects keep their original appearance until you deliberately choose the new setting.

Behavior: The new routing mode tries to move the selected arrow around both earlier and later visible arrows in the current screen projection. It also recognizes straight-segment overlaps and T-junctions that a strict crossing test misses. The arrow still connects exactly the same semantic nodes and retains its exact mathematical label. Unlabeled, invisible or overlapping historical constructions remain in your editable JSON project.

Limits and warning: This is a bounded, two-pass local refinement of existing node-avoiding corridors, not a globally optimal graph layout, a guarantee of crossing-free diagrams, or a sophisticated obstacle-maze solver. It considers at most 48 drawable arrows. When a crossing remains, a corridor is blocked, or a safety limit is reached, the arrow appears dashed amber with a tooltip; change positions, spacing or routing manually. Exact stroke/arrowhead interactions and Bézier crossings are still approximations.

Performance/export: The extra checks cost processing time. A 16-node/20-arrow isolated Chromium scene measured median redraw 2.10 ms Direct and 2.75 ms in this mode; no universal FPS guarantee follows. SVG/PNG/WebP reflect the current visible route, and native JSON v1 stores the choice for later editing. The limited TikZ visual exporter is disabled because it cannot reproduce that route precisely; tikz-cd is semantic interchange, not appearance-preserving export. Check page cropping and font placement in the final exported figure.
