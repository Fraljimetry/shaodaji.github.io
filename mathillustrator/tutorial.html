MathIllustrator · User tutorial

Release v0.1 — initial working editor. This tutorial documents behavior implemented in this exact release. MathIllustrator is an independent, local-first mathematical illustration project. It does not communicate with MathReader.

The long-term ambition covers geometry, analysis, topology, differential geometry, diagram chasing, Möbius transformations, real 3D, interactive mathematics, and publication-quality LaTeX. Those advanced features are not implied to exist in v0.1. Unsupported operations are described below.

1. Workspace layout

The left panel shows objects in reverse drawing order, a textual construction input, and the editable properties of the selected object. The center is a Cartesian drawing canvas. The right panel contains categorized icon-and-caption tools, workspace presets, a priori correction and snapping controls, new-object style, and canvas preferences. Click the chevrons beside either panel heading to collapse that panel.

The geometric convention is standard: positive x points right; positive y points up. SVG drawing uses a transformed screen coordinate system internally. The displayed viewport, zoom, grid, and selection are editor UI state; the project stores mathematical coordinates.

The endpoint snap check occurs before each segment/circle/polygon point is created. When sufficiently close to an existing point, the object references it, so movement of that point updates the construction. Auto-created endpoints are real point objects visible in the left list.

Selection: To move an existing point, switch to Move, then drag it on the canvas. Derived midpoints cannot be dragged independently; move their defining endpoints. Hold Shift while dragging blank space with Move to pan. Mouse wheel zooms around the cursor; the stage buttons zoom, reset the viewport, or fit visible points. Delete removes a selected object and every transitively dependent object to prevent dangling references.

3. Programmatic construction

Type a construction in the upper-left input and press Enter. Syntax is case-sensitive for names, except for geometric command keywords:

A = (0, 0)
B = (4, 2)
C = (-1, 3)
Segment(A, B)
Arrow(A, C)
Line(A, C)
Circle(A, B)
Polygon(A, B, C)
Polyline(A, B, C)
Midpoint(A, B)
f(x) = sin(x) + x^2/4

Point names must be unique. Construction commands accept named points and previously defined midpoint objects. Midpoint(A,B) is derived dynamically. Geometric objects reference point IDs rather than copying coordinates, so changes propagate immediately. Geometric tools and textual commands share one object model.

Supported function syntax

Functions graph y=f(x) in the current view. The deterministic parser supports numbers, x, pi, e, parentheses, + - * / ^, and the one-argument functions sin cos tan asin acos atan sqrt abs log ln exp floor ceil. Explicit multiplication is required: write 2*x, not 2x. Angles are in radians. Powers are right-associative. Functions are sampled (not algebraically solved), and discontinuities may be imperfectly rendered. Code evaluation, assignments inside formulas, arbitrary JavaScript, differential equations, implicit curves, inequalities, parametrized 3D curves, sliders, and solving systems of equations are not supported.

4. Object editing and dependency behavior

Select an object in the left panel or canvas. The properties editor lets you rename it, change color, stroke width and opacity, and edit point coordinates; text and function objects expose their content. Visibility and locking controls appear beside every object. The list is in z-order with most recent objects first; selected objects can move one step forward in drawing order. If a referenced point is moved, its dependent segment, circle, polygon, arrow, line, or midpoint updates on the next draw.

Currently individual objects are not all draggable: only free points can be directly moved. Grouping/layers, object reparenting, advanced constraints, arbitrary mathematical definitions, 3D selection and custom object templates are planned, not present. If you delete an anchor point, dependent constructions are deleted with it after their IDs are found; JSON Save beforehand if uncertain.

5. Presets, snapping, correction, pages

Choose a preset in the right panel: General, Olympiad geometry, Research diagram, Analysis / plots, or Free illustration. A preset changes future drawing defaults and canvas settings but does not restyle existing objects. Adjust these individually afterward:

  • Snap to grid: applies before creating/cursor-moving point objects. Snap interval is expressed in mathematical coordinate units, not CSS pixels. Reference snapping occurs within about 10 screen pixels of existing points.
  • Correction: Off preserves sampled pointer path; Gentle performs light smoothing, Medium stronger smoothing/simplification, Strong still more smoothing. It is applied immediately on finishing a freehand stroke. It does not yet recognize circles, straight lines, symmetry, tangency, handwriting, or arbitrary shapes. Existing paths are not automatically recomputed after the setting changes.
  • Grid / axes: show or hide drawing guides. Grid density adapts to zoom; this can differ visually from the snap interval.
  • Page: Infinite canvas or a centered A4/Letter landscape visual guide. The current page frames are visual guides only; no print-accurate dimensions or crop-to-page functionality exists yet.
  • Appearance: background, future object stroke/fill/line width and app light/dark theme. Appearance settings are distinct from existing object styles.

6. Save, open, undo, and persistence

Save downloads an editable mathillustrator.json project. Open imports that file after schema and dependency checks. Project metadata, objects, references and settings are retained. The browser also attempts debounced local autosave. Browser storage can be denied, cleared, or unavailable; local persistence is not a substitute for regularly downloading JSON. The native project schema is versioned: version: 1. Unsupported versions are rejected rather than silently downgraded.

Undo / Redo preserve up to 80 document-state snapshots per session. Dragging a point creates one undo entry for the entire completed gesture, not one per pointer event. View pan/zoom, UI themes, and current tool are not undoable. Importing or starting a new project is undoable within the current session, but not after reload. Do not edit JSON by hand without validating coordinates, object IDs and references.

7. Export formats and important limitations

FormatStatusNotes
SVGEnabledScalable image of the current viewport. Mathematical dependency semantics are not embedded.
PNG, JPEG, WebPEnabledRendered in-browser at 2× viewport resolution. If the browser rejects a format, conversion fails visibly rather than disguising the output.
JSONEnabledOnly format preserving editable MathIllustrator object IDs, coordinates and dependencies.
TikZ / PGFConditionalSimple points, lines, circles, polylines, polygons, free curves, text; disabled for function plots. Output uses literal coordinates, not preserved symbolic dependencies. Requires TikZ loaded by LaTeX.
PDF, Asymptote, tikz-cd, GIF, videoDisabledNot implemented. Disabled choices cannot be clicked or silently substituted.

TikZ import, native semantic LaTeX roundtrip, and tikz-cd are future requirements, not working features in this release. LaTeX labels are currently plain text in the editor; entering TeX text does not typeset it. Raster export flattens all math semantics. The SVG export can include the currently visible grid and axes, matching the viewport.

8. Current limitations and troubleshooting

  • Browser rendering: SVG is the first renderer and has not been performance-validated on 1,000+ complex objects. Large freehand strokes can create many path points. Performance figures have no fixed guarantees yet.
  • Geometry: No general geometric solver, intersection, perpendicularity, equal-length constraints, auto-label placement, angle markers, circumcircle construction, custom Bézier editing, curved arrows or shape recognition.
  • Advanced math: No 3D scene, Ricci flow engine, complex-plane Möbius transformation grid, ODE solver, animation or dynamic timeline, algebraic topology diagram semantics, or data charts.
  • Viewport: Zoom can be reset; Fit uses visible free points and freehand paths but not full extents of circles, curves or long lines. The A4/Letter page guide is not physical page sizing.
  • Invalid projects: If Open refuses a JSON file, examine the error toast and preserve the original rather than overwriting it. Cyclic/dangling dependencies and unsupported format versions are rejected.
  • Import/export fidelity: SVG and raster are graphic representations. TikZ export represents object geometry without construction relations; text escaping is basic. Preview the LaTeX result in your own TeX environment before submitting a publication.
  • Accessibility / touch: Keyboard operations cover command input, undo/redo, delete, polyline finish, and tools. Full keyboard-only drawing and multi-touch gestures have not been implemented/tested.

9. What comes next

The development plan separates a semantic editor core, advanced geometric constructions, diagram nodes/morphisms and LaTeX round-trip, numerical/complex plotting, 3D visualization, animation, and export infrastructure. See docs/ in the project overlay for JSON feature records, schemas, architectural decisions, exact regression status and unresolved issues. The tutorial must be updated whenever implemented behavior changes.
